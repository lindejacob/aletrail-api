# Entity Framework Core Migrations Guide

## Overview
Your project is now configured to use Entity Framework Core migrations to manage database schema changes. The migration has been created automatically and will be applied when the application starts.
## Creating New Migrations

When you modify your entity models, follow these steps:

### Step 1: Update Your Model
For example, if you want to add a `CreatedAt` field to the User model:

```csharp
public class User
{
    // ...existing properties...
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
}
```

### Step 2: Create a Migration
Run the following command:

```bash
/home/username/.dotnet/tools/dotnet-ef migrations add AddCreatedAtToUser
```

Or if you've added `~/.dotnet/tools` to your PATH:

```bash
dotnet-ef migrations add AddCreatedAtToUser
```

### Step 3: Review the Migration
A new migration file will be created in the `Migrations/` folder. Review it to ensure it looks correct.

### Step 4: Run the Application
Start your application normally:

```bash
dotnet run
```

The migration will be applied automatically to the database on startup.

## Useful EF Core Commands

### List All Migrations
```bash
dotnet-ef migrations list
```

### Remove the Last Migration (if not yet applied to DB)
```bash
dotnet-ef migrations remove
```

### View SQL Generated by a Migration
```bash
dotnet-ef migrations script
```

### Generate SQL for Specific Migration Range
```bash
dotnet-ef migrations script <from-migration> <to-migration>
```

### Update Database to Specific Migration
```bash
dotnet-ef database update <migration-name>
```

## Troubleshooting

### Connection Issues
If migrations fail due to database connection:
1. Verify PostgreSQL is running
2. Check connection string in `appsettings.Development.json`
3. Ensure the database exists (or PostgreSQL will create it)

### Migration Conflicts
If you have migration conflicts:
1. Back up your migration files
2. Remove conflicting migrations with `dotnet-ef migrations remove`
3. Recreate them with proper naming

### Tool Not Found
If you get "dotnet-ef not found":
```bash
dotnet tool install --global dotnet-ef
export PATH="$PATH:/home/username/.dotnet/tools"
```

## Best Practices

1. **Always review migrations** before running them in production
2. **Use descriptive migration names** (e.g., `AddCreatedAtToUser` not `Migration01`)
3. **Keep migrations in version control** - commit them with your code changes
4. **Test migrations locally** before deploying to production
5. **Create one migration per logical change** - don't bulk multiple changes into one migration
6. **Run `db.Database.Migrate()` in startup code** - this ensures schema is always up-to-date
